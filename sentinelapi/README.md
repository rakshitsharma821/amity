# SentinelAPI: Zero-Trust API Vulnerability Scanner (24h Hackathon MVP)

SentinelAPI is an automated, zero-trust API vulnerability scanner designed to detect critical authorization flaws and data leaks in modern REST APIs described by OpenAPI 3.0 specifications.

Built entirely with **zero external dependencies** (Node.js built-ins for the target sandbox, Python 3 standard library for the scanner engine, and vanilla HTML5/JS for the dashboard), SentinelAPI provides high-precision security audits with zero installation friction.

---

## ⚠️ Ethics & Legal Warning (Safety Constraint)

> **CRITICAL NOTICE**: SentinelAPI is developed strictly for authorized security auditing, defensive gap analysis, educational research, and internal CI/CD compliance testing.
>
> Testing web APIs without explicit written permission from the system owner is illegal and unethical.
>
> **Safety Guardrails Enforced in Scanner:**
> - **Default Allowlist**: By default, SentinelAPI **refuses** to scan any host other than local loopback addresses (`localhost`, `127.0.0.1`, `::1`, `0.0.0.0`).
> - **Explicit Authorization Flag**: Non-localhost sandboxes require the `--i-am-authorized` CLI flag; without it, the scanner halts immediately.
> - **Credential & Secret Masking**: Discovered authorization tokens, passwords, and credit cards are strictly masked (`Bearer eyJ...[redacted]`, `4532...[redacted]...1235`) in logs, terminal output, and saved reports.
> - **Bounded Request Bursts**: Rate limiting checks use strictly bounded bursts (default: 30 requests) to guarantee target systems are never degraded or denial-of-serviced.

## 🚀 Quickstart: Running in 3 Commands

SentinelAPI requires **no packages to install** (`no npm install`, `no pip install`). Only standard `node` and `python` runtimes are needed.

### Step 1: Start the Vulnerable Mock API
In your first terminal, launch the intentionally vulnerable target server:

```bash
node sentinelapi/vulnerable-api/server.js
```
*Listens on `http://localhost:4000`. Exposes OpenAPI spec at `http://localhost:4000/openapi.json`.*

### Step 2: Run the SentinelAPI Scanner
In your second terminal, execute the scanner against the target:

```bash
python sentinelapi/scanner/scanner.py --config sentinelapi/scanner/config.example.json --out sentinelapi/findings.json
```
*To test CI/CD gating, append `--fail-on high` to exit with status code `1` if High-severity flaws exist.*

### Step 3: View the Interactive Security Dashboard
Double-click or open `sentinelapi/dashboard/index.html` directly in any web browser:

```bash
# Windows
start sentinelapi/dashboard/index.html

# macOS
open sentinelapi/dashboard/index.html

# Linux
xdg-open sentinelapi/dashboard/index.html
```
*The dashboard operates completely offline from `file://` with embedded baseline findings and includes a **"Load findings.json"** button to load any custom scan.*

## 🔍 Vulnerability Checks & Detection Methodology

| Check Type | OWASP API Top 10 | Severity | Detection Logic |
| :--- | :--- | :---: | :--- |
| **BOLA / IDOR** | API1:2023 | **High** | Authenticates two test identities (`user_a` and `user_b`). Discovers resource IDs and requests `user_b`'s private entity using `user_a`'s token. Flags **only** if status is `200 OK` **and** the response matches the resource owner's body, eliminating false positives on public endpoints. |
| **Payment Card Exposure** | API3:2023 | **High** | Recursively traverses JSON response payloads and validates potential primary account numbers (PAN) using the ISO/IEC 7812 **Luhn checksum algorithm** to catch unmasked credit cards. |
| **Credential Exposure** | API3:2023 | **High** | Recursively scans JSON payloads for sensitive keys (`password`, `passwd`, `secret`, `api_key`, `token`) returning plaintext credentials. |
| **Missing Rate Limiting** | API4:2023 | **Medium** | Sends a bounded burst (30 requests) to the authentication endpoint (`/login`). Flags if no HTTP 429 status and no rate-limit headers (`Retry-After`, `X-RateLimit-*`) are returned. |

## 🛠️ Configuration Schema (`config.json`)

The scanner is completely configuration-driven and can be run against any OpenAPI 3.0 API:

```json
{
  "target": {
    "base_url": "http://localhost:4000",
    "spec_url": "http://localhost:4000/openapi.json",
    "spec_file": ""
  },
  "auth": {
    "login_endpoint": "/login",
    "method": "POST",
    "token_json_path": "token",
    "token_header_prefix": "Bearer ",
    "users": {
      "user_a": {
        "name": "Alice (Attacker Context)",
        "credentials": { "username": "alice", "password": "alice123" },
        "seed_ids": { "orders": [1, 2], "users": [1], "default": [1] }
      },
      "user_b": {
        "name": "Bob (Victim Context)",
        "credentials": { "username": "bob", "password": "bob123" },
        "seed_ids": { "orders": [3, 4], "users": [2], "default": [2] }
      }
    }
  },
  "checks": {
    "bola": { "enabled": true },
    "excessive_data_exposure": {
      "enabled": true,
      "sensitive_fields": ["password", "passwd", "card_number", "cvv", "ssn", "token", "secret", "api_key"],
      "detect_luhn_cards": true
    },
    "rate_limiting": {
      "enabled": true,
      "burst_count": 30,
      "endpoint": "/login",
      "method": "POST"
    }
  }
}
```

## 🛡️ Finding Report Structure

Every finding generated by SentinelAPI includes:
1. **Unique ID**: (e.g., `SENTINEL-BOLA-01`)
2. **Title & Class**: Categorized by OWASP API Security Top 10.
3. **Severity**: `High`, `Medium`, or `Low`.
4. **Endpoint**: Method and parameterized route template (`GET /orders/{id}`).
5. **Plain-English Explanation**: Plaintext synopsis for non-technical stakeholders and executive leadership.
6. **Masked Evidence**: Real payload responses with sensitive credentials and PANs redacted.
7. **Runnable cURL PoC**: Safe copy-paste command for developers to reproduce the issue.
8. **Concrete Recommendation**: Precise remediation instructions (e.g. data access layer ownership validation, DTO filtering, token bucket rate limiters).

## 🔮 Future Extension Ideas

1. **LLM-Assisted Test Prioritization**:
   Use an LLM agent to analyze OpenAPI route descriptions, schemas, and parameter names to automatically infer business-critical endpoints (e.g., invoices, checkout, profile settings) and prioritize aggressive testing on high-risk surfaces.
2. **Multi-Step Agentic Chains**:
   Support stateful API sequences (e.g., `POST /orders` -> extract `id` -> attempt `DELETE /orders/{id}` using another tenant's session).
3. **POST / PUT / DELETE State-Mutation Coverage**:
   Extend BOLA detection to state-changing methods with automatic rollback / sandbox database resets.
4. **Automated CI/CD Quality Gates**:
   Integrate with GitHub Actions or GitLab CI using `--fail-on high` to block deployments when unauthorized data leakage or BOLA regressions occur.
5. **GraphQL & gRPC Gateway Adapters**:
   Translate GraphQL schemas or protobuf definitions into standardized query trees for cross-protocol authorization testing.
